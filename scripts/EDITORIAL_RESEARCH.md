# 国内经营研究上线说明

本阶段改造每日信号与周报案例生产线。机会库继续从已发布信号聚类；历史文章不自动补造经营地区或证据。

## 开启顺序

1. 部署本次代码（默认开关关闭，不影响旧生产线）。
2. 在 Supabase SQL Editor 执行 `supabase/migrations/20260910_editorial_research.sql`。成功通常显示 `Success. No rows returned`。
3. Vercel 服务端环境变量设置 `EDITORIAL_RESEARCH_ENABLED=true`，重新部署。
4. GitHub 仓库 Settings → Secrets and variables → Actions → Variables（不是 Secrets），增加同名变量 `EDITORIAL_RESEARCH_ENABLED=true`。
5. 手动执行 Daily Radar，先勾选 dry_run。查看摘要中四类经营地区数量、国内占比与拒收原因。真实国内候选不足必须公开报告缺口，不能把中文素材重新标成国内。
6. 后台 → 待审核 → 国内案例研究，添加线索或核实证据；手动执行 Weekly Newsletter 后在周报页审核草稿。代码不会替管理员勾选核实，也不会代发合作邀约。

开关启用后，新信号和周报都只写草稿。发布接口检查六问与来源使用依据；旧草稿缺少这些信息会被阻止发布，应先审核处理旧草稿或重新生成，不能编造历史证据。已发布历史内容保持原样。

## 来源与配额

- 官方公开 RSS：w2solo `/topics/feed`、V2EX 分享创造 `/feed/create.xml`，保留少数派及原海外来源。
- 2026-09-10 本机实测：w2solo HTTP 200、解析20条；V2EX连接被重置，尚需 GitHub runner 验证，不宣称已稳定接通。
- 每个社区先过具体业务用途预筛；国内判定需要经营地区证据，不依赖语言/来源。模型后续仍可拒收。
- “候选池”指实际送审入模的池，不是原始 RSS 收件箱：最多54条，国内预留27，其他合计最多27；国内不足不扩大海外配额。国内只占一部分时如实报告比例。来源仍有独立上限，大公司最终最多1条。
- 设计、内容、电商、知识产品、小企业服务、软件分别标记 business_form；旧 category 保留以兼容现有导航。
- 每周先尝试1–2篇管理员核对的国内案例，不保证数量。即使只通过1条，开启新模式后也保留草稿；不再为达到5条丢掉已有合格研究。整体仍以6条为目标，已有5条的旧停止策略暂保留。
- 不批量抓取独立开发前线采访全文、小报童付费正文、公众号受限正文或生财会员内容。作者官网公开事实可人工核对入队列；授权需记录人、日期、范围、凭证位置。

## 权限与证据

`editorial_research` 仅 service_role 可读写，无普通用户 RLS 策略。lead_url、research_question、permission_note 不送大模型、不进公开页面、不进公共 RSS。仅 verified 记录的独立来源和必要摘录送写稿；模型不能自行授予授权。

六问各自标注来源陈述 / 编辑推断 / 未披露。问题、AI作用与证据必须有素材内逐字引用；收入或客户自述不等于审计。证据 C 为公开线索，B 为人工核对来源，不自动给 A，也不按机会评分反推证据等级。

经营地区使用保守的明确表述规则。计划、假设、混合市场或无明确客户地区的素材保留 unknown；目前不能识别所有城市/国家别名，宁可待核实，不凭国籍推断市场。

研究摘录是人工核对的必要事实，不是全篇转载许可。公开 ≠ 可复制全文；作者授权也不自动覆盖他人的客户数据和图片。新模式默认不抓取第三方封面图。

## 验证与回滚

运行 `npm run typecheck`、`npm run test:all`、`npm run build`。
本机没有生产 Supabase / 智谱凭证时，不执行真实写稿或生产数据库写入；单元测试样本只在测试目录，不写入真实站点。
回滚时将 Vercel 与 GitHub 的开关都设为 false 并重新部署，保留数据库新增字段/内部研究记录，不删用户数据。不要删除原始来源、隐去未知或降低标准以制造“成功”。
