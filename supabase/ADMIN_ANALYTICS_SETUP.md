# 管理员数据概览：启用与口径

## 一次性启用

1. 在对应生产 Supabase 项目打开 **SQL Editor → New query**。
2. 粘贴并执行 `supabase/migrations/20260907140000_admin_analytics.sql` 全文。脚本可以重复执行；不会删除已有访问日志、累计数、探索会话或用户。它会撤销匿名和普通登录用户对访问统计表的权限，并回填已验证邮箱的注册时间。
3. Vercel 服务端须已有 `SUPABASE_SERVICE_ROLE_KEY`、`NEXT_PUBLIC_SUPABASE_URL` 和 `ADMIN_PASSWORD`。不要把服务端 Key 放入 `NEXT_PUBLIC_*` 变量。本功能没有新增付费服务。
4. 在 `/admin` 登录管理员账号，即可在审核台顶部看到数据概览。未迁移/读取失败时显示“未配置/不可用”，不会以零伪装。
5. 用另一个非管理员浏览器访问公开机会详情并停留至少 10 秒；完成邮箱验证、生成非演示规划、点击“保存研究结果”。返回管理员概览点击“刷新数据”验证。不需要进行真实支付。

## 统计口径

- 时间：北京时间（Asia/Shanghai），7/30 天均含今天，今天是截至查询时刻的部分数据。
- 今日访客：匿名浏览器 Cookie 按天去重。近 7/30 天访客按周期去重，不是每天人数相加，也不是自然人数。Cookie 签名、HttpOnly、SameSite=Lax，生产环境 Secure，有效期 90 天。
- 累计访问数：保留旧计数，从启用后加每日浏览器访客；不同时间的旧、新口径不能作为精确累计独立人数。
- 新增注册：Supabase `email_confirmed_at`，首次邮箱验证成功。仅申请验证码但未验证不算注册。可从已有账号记录回填，用户被删除后关联事件也随之删除。
- 活跃用户：周期内有登录活动、访问或研究/保存行为的已登录账号去重。匿名浏览不算登录活跃用户。
- 探测器完成数：客户端收到非演示模型规划，具有愿景、第一步与里程碑时，上报一次完成；仅登录用户可上报，重新生成另计一次，同一事件重试去重。它是产品遥测，**不是不可伪造的服务端业务凭证**，也不证明研究质量；网络故障/拦截可能漏报。
- 保存用户：服务端成功保存了带本次埋点版本非演示规划标识的探索后，按用户去重；空进度、演示规划、旧版无标识的历史结果不计入该新指标。同会话同用户同天去重。
- 阅读机会：已发布机会详情处于前台可见状态累计至少 10 秒；不采集滚动、正文或完整 URL 参数。该信号不能证明用户确实理解内容。
- 未采集历史行为：图表/明细为“—”，启用当天标记为部分数据，不回填伪造历史。注册历史独立回填。

## 漏斗

访问 → 阅读机会 → 首次注册 → 完成方向研究 → 保存结果或付费。

同一时间窗口内先后完成各步才算转化。匿名 Cookie 在登录后关联经服务端验证的账号标识；后续完成与保存可跨设备。最后几步必须为同一账号，不把共享浏览器中两个人的动作拼接。单位仍为起点浏览器访客，清除 Cookie、跨浏览器重复访问、统计拦截可造成差异。原有账号直接研究仍计入活跃/完成指标，但不作为新注册漏斗转化。

## 付费预留

仅预留服务端 `recordVerifiedPayment(userId, provider, transactionId)`。未来支付服务必须先验签、校验订单归属/金额/成功状态，再调用。`provider + transactionId` 幂等。公共事件接口拒绝 `payment_completed` 和 `registered`；没有支付按钮、收费行为、虚构收入或付款成功端点。当前 UI 明确显示未接入。

## 权限与隐私

统计概览与旧 `/api/views` 的 GET 仅接受签名管理员 Cookie，响应 `private, no-store`；旧 POST 返回 410。数据库统计表开启 RLS 并撤销 public/anon/authenticated 权限，服务端 service_role 才能写入/查询。**必须执行迁移，才能同时关闭原有数据库直读入口。**

行为统计不记录邮箱、IP、研究内容、访客指纹或查询参数。管理员 Cookie、已识别机器人和 DNT/GPC 请求不记录行为；注册时间属于账号生命周期记录，独立处理。随机新 Cookie 仍可能伪造访问，不用于广告计费或反欺诈。当前单实例速率限制与数据库幂等只能降低重复，不能替代全局反滥用系统。

事件不包含研究正文。未引入自动删历史日志的定时任务。后续如要做事件保留/聚合策略，应先明确保留期限。

## 验证

`npm run test:analytics` 验证时区、周期去重、漏斗顺序、跨设备、共享设备和 API 鉴权。

可在临时目录安装 `@electric-sql/pglite`，设置 `ANALYTICS_PGLITE_PATH` 为该包目录后运行 `npm run test:analytics:db`，验证真实 PostgreSQL 的迁移幂等、注册触发器、RLS/权限和累计计数。不会连接生产数据库。

管理员查询使用固定时间上界和 ID 游标分页，不静默丢弃超过 1000 条的记录；若 30 天超过 50000 条，返回明确错误，应迁移为数据库聚合后再扩大上限。
