# P1 统一阅读、周报复用与反馈

目标读者：个人内容创作者、AI 应用开发者、设计师与 AI 一人公司。默认入口只展示审核发布的资讯，X 来源动态明确标注为未精选线索。

## 功能
- `/news` 为统一入口，支持主题、信源筛选；`/radar` 与 `/x` 永久重定向，旧历史周报地址保留。
- `/news/r-<uuid>` 提供来源日期、收录日期、适用范围、原文、反馈及直达二维码。X 动态仅跟踪中且启用的账号可见。
- `/admin/briefs` 选择已发布资讯组成周报；`/briefs/<周一日期>` 按引用顺序读取当前资讯。下架内容自动消失，修改无需重复生成。
- 二维码本地生成 SVG，固定指向正式域名的对应详情，带 `from=wechat`。复制链接带 `from=share`，RSS 带 `from=rss`。
- 统计按来源、主题、渠道展示最近30天计数；跨日复访是同一匿名浏览器在至少两个北京时间自然日访问，不是真实人数。管理员、常见爬虫、DNT/GPC 不计入。反馈可修改。

## 部署
1. 应用 `supabase/migrations/20261117160000_news_reading.sql`，新增三张仅服务端访问的表；迁移可重复执行，不删除历史数据。
2. Vercel 继续使用现有 Supabase 服务端配置与 ADMIN_PASSWORD，无新增模型密钥。
3. `NEWS_PIPELINE_ENABLED=true` 时新工作流每周一北京时间08:15生成上个完整周的引用草稿，不调用模型、不自动发布、不覆盖已有周报，没有资讯就不凑数。旧研究周报工作流暂停。
4. 后台审核草稿后发布；不要为了测试而发布低价值或重复内容。

## 指标边界
- 内容展示：进入可视范围并停留1.2秒，或打开详情；展示/点击按浏览器与内容去重。分享是操作数，不是实际传播人数。
- 最近200条已发布资讯、100条来源动态；周报最多30条、后台最近52期。不是无限历史搜索。
- 统计读取完整范围，超过50,000条返回错误，不展示截断后冒充完整的数字。
- 浏览器禁用统计、网络失败、换设备或清 Cookie 都会影响计数。上线前没有历史数据。
- 迁移前周报读取为空、统计明确报不可用；不是数据为零。

## 验证
`npm run test:all`、`npm run typecheck`、`npm run build`。新增 PGlite 测试覆盖私有表权限、重复迁移、草稿隔离、版本冲突、事件去重、反馈更新；纯函数覆盖精选/X隔离、URL去重保留业务参数、上海周界与复访口径。上线另验已发布内容、筛选、二维码、移动布局和后台真实写入。

回滚应用代码不删除三张新增表或历史内容；恢复旧周报调度需同步调整功能变量，避免两条自动流水线并行。

## 旧内容过渡
新资讯入口、详情、周报选编和自动草稿均要求存在新版采编记录且状态为 published；旧雷达即使此前已发布也不能直接进入精选。旧周报不再混入新版归档和 RSS；原链接仅供历史回查。旧雷达在新版前台下架，数据库记录保留，可逐条复核后迁移，不能批量视为新标准已审核。
