# AI OPC 周报编辑规范

版本：1.0 · 生效日期：2026-09-14 · 适用范围：周报选题、来源维护、模型研究、人工审核与报告呈现。

本规范以第44期补充研究的实际交付及用户人工审核反馈为基准。它是后续周报的编辑依据；问题排查历史见 [研究策略与运行复盘](WEEKLY-RESEARCH-STRATEGY.md)，合格样本见 [2026-W38 审核记录](editorial-reviews/2026-w38.md)。规范变化应同时核对实现与样本，不把一次模型评分当成永久结论。

## 1. 定位与读者价值

服务设计师、开发者、内容创作者与专业服务者，帮助一个人更有依据地选择创业方向、设计交付，并开展小规模验证。软件、设计服务、内容、电商、知识产品与自动化服务均可入选。

每日信号回答“发生了什么新变化”；周报必须进一步回答“谁为什么会付钱、AI在哪个环节创造价值、一人能切入哪部分、如何验证、什么情况下应停止”。收藏价值来自可复用的方法和判断依据，不能只把每日信号扩写成长文章。

每期目标6篇，最低完整交付5篇，每篇均须有完整研究报告。数量不足时继续补来源与研究，不用融资、热度、模型更新或空泛工具介绍凑数。

### 2.3 日期、证据与来源维护

- 有发布日期的候选优先近30天，31–90天经营复盘可补位。没有发布日期的官网作为当前读取的经营案例，标明读取日期与日期未知，不包装成本周新发布。
- 已有素材不通过重复采集刷新原始日期。已收录产品及历史来源须去重。
- 付费社群、受限内容只作线索，研究应转向公开原文或已确认授权材料。公开可访问不等于全文转载授权。
- 官网陈述可证明其公开宣称的功能、定价与流程，不能自动证明真实收入、实际客户成效或收益承诺。当前单来源报告不称为交叉验证。
- 人工编辑每周维护新增经营页、失效链接与候选缺口，优先补读者可落地的设计、服务、内容、知识与软件案例；这是编辑维护职责，不是已经实现的自动发现保证。

## 3. 筛选流程与硬门槛

先发现候选，再读原文，再判断证据与研究价值，最后检查整期组合。关键词命中只决定是否继续研究，不能代表入选。

候选必须满足：

1. 有可读取的公开原文或已确认授权证据，能够追溯具体陈述。
2. 明确的客户问题与AI交付作用，问题、AI作用及证据三问均有原文支撑。
3. 有可解释的一人切入点，说明人机分工、依赖及边界。可以借鉴成熟公司的一个窄服务，不要求完整复制其平台。
4. 至少三条互不重复的事实引用，以及完整研究报告。推断、原文陈述和未知事项明确分开。
5. 加权总分至少75；客户问题、一人交付、证据深度各至少3/5。

收入、团队人数、经营地区未知，不自动拒稿；必须如实标注。中文、国籍、域名或“面向全球”不能代替经营地区证据。

以下内容不能直接入选：只有热度或融资；没有具体业务用途的技术发布；只有广告口号；没有可迁移经营方法的工具合集；依靠编造数据、翻译改写引文或模型记忆才能满足证据要求的内容。

## 4. 评分标准

每项0–5整数，加权总分为 `Σ(维度分 ÷ 5 × 权重)`。评分衡量研究与收藏价值，不代表创业成功率或收益预测。0–2表示缺失、含糊或明显不适合。

| 维度 | 权重 | 3分 | 4分 | 5分 |
|---|---:|---|---|---|
| 客户问题 | 20% | 泛化需求 | 明确人群、具体任务与损失 | 另有可核对的客户结果 |
| 商业逻辑 | 20% | 仅潜在变现 | 公开收费方式、交付物与流程 | 另有可核对的经营数据 |
| 一人交付 | 20% | 泛泛认为个人能做 | 两周可验证的窄切口，依赖与交付边界明确 | 有直接的一人经营证据 |
| 证据深度 | 25% | 简短宣传 | 至少三条不同原文具体支持客户问题、AI能力与收费/交付机制 | 有独立来源核实经营结果 |
| 可迁移学习 | 15% | 通用建议 | 具体可迁移方法、反例与验证动作 | 多个有证据支持的独特经营洞察 |

关键校准：没有经审计收入，不等于没有可研究的产品事实。单一官方来源的研究证据深度最高4分，公开来源的可信度仍按未独立核实处理；不能把未知收入在多个维度重复扣分，也不能为了达到75分反向编造依据。当前“最高4分”是模型与人工审核口径，通用结构校验并未单独强制这个上限，编辑审核须检查。

## 5. 整期组合

- 目标6篇，完整交付范围5–6篇；同一来源域名最多2篇，同一类别最多3篇。
- 同产品及历史来源去重；不同链接或不同标题不应成为重复收录的理由。
- 优先形成产品、服务、内容/知识/设计资产的组合，但只在合格候选存在时选取，不按地域或品类配额制造案例。
- 不足5篇：补原文、补经营案例、检查技术误拒、继续生成并保留成果。不能把“一篇已保存”报成整期完成。

## 6. 深度拆解报告标准

报告必须比卡片摘要提供新的判断与行动价值，避免把同一段产品介绍换标题重复六次。

| 模块 | 必须回答的内容 |
|---|---|
| 标题、导读与编辑判断 | 清楚的经营论点；值得借鉴什么，什么不应照搬 |
| 事实账本 | 3–5条不同事实、逐字引文、对应来源；每条引文8–120字符，事实引文总计不超过480字符 |
| 六问 | 谁付钱、解决什么问题、AI作用、一人交付、证据、风险；各标原文陈述/编辑推断/未知 |
| 客户分析 | 哪类客户、哪项任务、当前替代方案与接触入口 |
| 收费与成本 | 收费单位、付费理由、主要成本；不编造MRR、利润或市场规模 |
| 交付与人机分工 | 具体流程、人工责任、外部依赖、服务边界 |
| 获客 | 首批客户的具体接触动作与验证方法 |
| 差异化 | 可执行的窄切口与不宜照搬的条件 |
| 长期积累 | 能沉淀什么数据、流程、内容或客户资产 |
| 两周验证 | 第1–3、4–7、8–14天三个阶段；每阶段有行动、继续信号、停止标准，阈值标为建议实验标准 |
| 风险与未解问题 | 2–4项具体风险及核实方法，至少2项未披露/待验证问题 |
| 收藏价值 | 恰好3条可复用的经营原则 |
| 来源与方法 | 来源链接、原文日期（或未知）、读取时间；说明厂商陈述与编辑推断的边界 |

六段商业分析以每段120–220字为编辑目标；代码的最小长度校验不是写作目标。收入数据若未核实，不能用完整的报告结构掩盖其不确定性。

## 7. 单页呈现与产品体验

公开正文以客观第三人称为主，措辞克制，不用收益承诺或广告式夸张替代判断。

采用纸色背景、深墨正文、克制的蓝色标注、衬线论点标题、细线与充足留白。信息顺序为判断、事实、商业分析、验证计划、风险与来源，避免同质彩色卡片堆叠。

桌面有阅读目录，手机单栏无横向溢出；长标题、长引文和长链接可换行。事实引用可展开查看，支持收藏、分享、打印。关键判断不能藏在折叠内容里，打印应隐藏操作控件。

用户直接读取已生成并入库的报告，无需复制提示词到外部模型；页面访问不重复调用模型。草稿报告仅供管理员预览，公开访问遵循期数发布状态。

## 8. 生产、人工审核与交付

自动流程：周中预采集 → 周一分时生成/补足 → 单案例模型研究 → 引用与结构校验 → 逐篇保存 → 统计整期完整度。已发布版本不自动改写；明确需要补充时另建 `-supplement` 草稿，重复运行继续同一草稿。

本期成功使用GLM-4.7。模型配置以运行环境的真实密钥为准；支持DeepSeek不代表所有环境已经配置。模型、提示或来源读取规则变更后，应检查既有合格样本是否被误拒，以及新内容是否仍达到本规范，不能只看任务绿色状态。

人工发布前逐项确认：

- 读者能明确理解客户、AI作用和可执行切口，报告有收藏价值。
- 事实与引用相符，收入/客户成效不越过证据；推断没有伪装为已验证事实。
- 评分有对应依据，官方来源没有被当作独立审计。
- 行动计划、停止标准与反方风险足够具体，六段分析没有重复灌水。
- 组合无重复，数量5–6篇，每篇完整报告已入库，页面可阅读。
- 审核反馈与修改理由留档；“内容质量认可”不等于自动授权发布或独立核实经营数据。

交付以数据库实存数量及报告完整性为准。当前有 `Weekly Delivery Check` 只读核查任务；运行失败应区分来源不可读、原文不足、模型限流、格式误拒、质量不达标及保存失败。格式和网络失败不能当永久质量拒稿；评分口径改变时旧口径拒稿应重新评估。

## 9. 基准维护与实现位置

第44期六篇是本规范v1.0的合格样本，获用户批次级质量认可；不是每周固定选题，不意味着所有同类产品都合格。每次人工审核记录认可点、退稿原因与修改要求；涉及标准变化时更新版本及理由，避免只修改模型提示、遗忘文档。

| 实现 | 职责 |
|---|---|
| `scripts/lib/weekly-research-policy.mjs` | 信源、候选排序、权重、总分与组合门槛 |
| `scripts/fetch-weekly-sources.mjs` | 独立信源采集与官方经营页读取 |
| `scripts/lib/weekly-source-reader.mjs` | 原文读取与正文提取 |
| `scripts/lib/weekly-report-generator.mjs` | 评分锚点、报告提示、编号引文、结构验证 |
| `scripts/generate-weekly-research.mjs` | 逐篇入库、重跑与补充草稿 |
| `lib/weekly-report.mjs` | 完整报告与整期交付检查 |
| `components/weekly-research-report.*` | 单页报告呈现 |

研究库、发现渠道和代码阈值应与本规范同步维护。人工编辑要求与代码已实现检查需明确区分，不能把文档新增要求误报为已自动执行。
